##  메시 최적화

### 1️⃣ Element 수 줄이기

#### Element란?

Element는 폴리곤으로 이루어진 개별적인 메시 파트를 의미합니다. 하나의 Static Mesh 안에 여러 머티리얼 슬롯이 있다면, 각 슬롯이 하나의 Element가 됩니다.

#### 문제점

- Element가 많이 나눠져 있으면 UV 조각도 많이 나눠져 있습니다.
- UV 이음새(Seam)에 따라 버텍스 수가 증가하여 메모리 사용량이 늘어납니다.
- 각 Element마다 Draw Call이 발생하여 렌더링 비용이 증가합니다.

#### 해결 방법

- 3D 모델링 툴에서 불필요한 UV 이음새를 줄입니다.
- 가능하면 하나의 머티리얼로 통합합니다.
- Texture Atlas를 활용하여 여러 텍스처를 하나로 합칩니다.

---

### 2️⃣ 작은 메시 병합

작은 오브젝트들이 많으면 Draw Call이 증가하여 성능 저하의 원인이 됩니다. [[Actor Merge|액터병합]] 기능을 활용하여 여러 Static Mesh를 하나로 합칠 수 있습니다.

#### Actor Merge 사용 방법

1. 병합할 액터들을 선택합니다.
2. **Window > Developer Tools > Merge Actors**를 실행합니다.
3. 병합 옵션을 설정하고 새로운 Static Mesh를 생성합니다.

#### 주의사항

- 너무 많은 메시를 하나로 합치면 오히려 컬링 효율이 떨어질 수 있습니다.
- 동적으로 움직이거나 개별 제어가 필요한 오브젝트는 병합하지 않는 것이 좋습니다.

---

### 3️⃣ 불투명과 반투명

#### Z-Buffer Culling

```
r.VisualizeOccludedPrimitives 1
```

콘솔 명령어로 Z 버퍼 컬링을 시각화할 수 있습니다. 
초록색 박스가 표시되면 정상적으로 작동하는 것입니다.

**작동 원리**
- Z 버퍼는 카메라로부터의 깊이 정보를 저장합니다.
- 다른 오브젝트에 완전히 가려진 오브젝트는 렌더링하지 않습니다.
- 컬링 기준은 오브젝트의 바운딩 박스입니다.

#### 반투명 오브젝트의 문제

- 반투명 오브젝트가 겹치면 각각을 모두 렌더링해야 하므로 매우 무겁습니다.
- 렌더링 순서가 꼬이면 시각적 문제(정렬 오류)가 발생하기도 합니다.

#### 해결 방법

- **반투명 정렬 우선순위(Translucent Sort Priority)** 설정으로 렌더링 순서를 명시적으로 지정합니다.
- 반투명 오브젝트의 개수를 최소화합니다.
- 가능하면 Masked 블렌드 모드를 사용합니다 (알파 테스트 기반으로 더 가볍습니다).

### 메시 모델링 권장사항

#### 4️⃣ 5각형 폴리곤과 고폴리곤 메시 사용 자제

- 게임 엔진은 삼각형 기반으로 렌더링하므로, 5각형 이상의 폴리곤은 자동으로 삼각분할(Triangulation)됩니다.
- 이 과정에서 예상치 못한 삼각형 배치가 발생하여 셰이딩 문제가 생길 수 있습니다.
- 모델링 단계에서 쿼드(4각형)나 트라이(3각형)로 정리하는 것이 좋습니다.

#### 5️⃣ Skeletal Mesh 사용 최소화

Skeletal Mesh는 본(Bone) 변형 계산이 추가되므로 Static Mesh보다 무겁습니다.

**대안**
- 움직이지 않는 장식 요소는 Static Mesh로 제작합니다.
- [World Position Offset](app://obsidian.md/World%20Position%20Offset)을 활용하여 간단한 애니메이션은 머티리얼로 구현할 수 있습니다.

#### 6️⃣ 테셀레이션은 미리 적용하기

- 런타임 테셀레이션(실시간 폴리곤 세분화)은 GPU 부하가 큽니다.
- 3D 모델링 툴에서 테셀레이션을 미리 적용한 후 익스포트하는 것이 훨씬 가볍습니다.
- 필요하다면 [LOD](app://obsidian.md/Level%20Of%20Detail) 시스템과 조합하여 거리에 따라 디테일을 조절합니다.

---

### 7️⃣ 큰 메시는 나누기

#### 컬링 효율성

크기가 매우 큰 메시는 일부만 화면에 보여도 전체를 렌더링해야 하므로 비효율적입니다.

**Visibility Culling 시각화 CVar**

```
FreezeRendering
```
 
- 현재 시점에서 렌더링을 고정하여 컬링 상태를 확인할 수 있습니다.
- 화면 밖의 에셋이 제대로 컬링되는지 확인하세요.

#### 분할 기준

- 바운딩 박스가 화면 크기를 넘어가는 메시는 여러 조각으로 나누는 것을 고려합니다.
- 건물의 층별로, 또는 방별로 나누면 컬링 효율이 향상됩니다.

## 머티리얼 최적화

### 8️⃣ Material Default Texture (머티리얼 기본 텍스처)

마스터 머티리얼의 기본 텍스처는 **64×64** 크기를 권장합니다.

#### 이유
- 머티리얼 인스턴스에서 텍스처를 오버라이드하지 않으면 기본 텍스처가 사용됩니다.
- 기본 텍스처가 불필요하게 크면 메모리를 낭비하게 됩니다.
- **64×64는 Place Holder**로 충분하며, 실제 사용하는 텍스처는 인스턴스에서 지정합니다.

---

### 9️⃣ 텍스처 해상도 줄이기

#### Bilinear Filtering (바이리니어 필터링)

텍스처가 작을수록 화면에 표시될 때 자동으로 부드럽게 보간됩니다. 이를 바이리니어 필터링이라고 합니다.

**Texture LOD Bias**
- **Texture Properties → LOD Settings → LOD Bias**로 텍스처 해상도를 조절할 수 있습니다.
- 양수 값을 입력하면 낮은 해상도의 밉맵을 사용하여 메모리를 절약합니다.
- 너무 높은 값은 텍스처가 지나치게 흐려지므로 주의가 필요합니다.

### 1️⃣1️⃣ Shading Model (셰이딩 모델)

셰이딩 모델에 따라 렌더링 비용이 달라집니다.

**성능 순서 (가벼운 것부터)**
1. **Unlit**: 라이팅 계산 없음, 가장 가볍습니다.
2. **Default Lit**: 기본 PBR 라이팅, 대부분의 경우 적합합니다.
3. **Subsurface**: 반투명 산란 계산 추가, 피부나 초 등에 사용합니다.
4. **Clear Coat**: 다층 반사 계산, 자동차 페인트 등에 사용합니다.

불필요하게 복잡한 셰이딩 모델을 사용하지 않도록 주의합니다.

## 라이팅 최적화

### 1️⃣2️⃣ Light Complexity (라이트 복잡도) 확인

뷰포트 상단의 **View Mode → Optimization Viewmodes → Light Complexity**를 선택하면 라이팅의 부하를 시각적으로 확인할 수 있습니다.

**색상 의미**
- **검은색/어두운 색**: 라이팅 부하가 적습니다.
- **밝은 색/흰색**: 여러 라이트가 겹쳐서 부하가 큽니다.

### 1️⃣3️⃣ Rect Light 사용 자제하기

Rect Light(면 광원)는 부드러운 그림자와 현실적인 조명을 제공하지만, 연산 비용이 매우 높습니다.

**대안**
- Point Light나 Spot Light로 대체합니다.
- IES 프로파일을 활용하여 빛의 형태를 조절합니다.
- Lightmass를 사용한 베이크드 라이팅을 고려합니다.

---

### 1️⃣4️⃣ Cull Distance Volume (컬 디스턴스 볼륨) 사용하기

작은 오브젝트는 멀리서 보이지 않아도 렌더링할 필요가 없습니다.

#### Cull Distance란?

설정된 가시거리보다 멀리 있으면 렌더링하지 않는 기능입니다.

#### 설정 방법

1. **Volumes**에서 **Cull Distance Volume**을 배치합니다.
2. 볼륨 내부의 오브젝트들에 대해 크기별 컬링 거리를 설정합니다.
3. 예: 작은 돌멩이는 500 유닛 이상 멀어지면 렌더링하지 않음.


---

### 1️⃣5️⃣ LOD 적극 활용

[LOD](app://obsidian.md/Level%20Of%20Detail)는 거리에 따라 폴리곤 수가 다른 모델을 자동으로 전환하는 시스템입니다.

#### LOD 설정 권장사항
- **LOD 0**: 원본 고품질 모델 (카메라 가까이)
- **LOD 1**: 중간 품질 (~50% 폴리곤 감소)
- **LOD 2**: 낮은 품질 (~75% 폴리곤 감소)
- **LOD 3**: 매우 낮은 품질 또는 임포스터

언리얼 엔진의 자동 LOD 생성 기능을 활용하거나, 모델링 툴에서 직접 LOD를 제작할 수 있습니다.

### 1️⃣6️⃣ 라이트 소스 병합 트릭

여러 개의 작은 라이트 대신 하나의 큰 라이트를 사용하면 성능이 향상됩니다.

![Pasted image 20240702231101.png](app://17fa551dc7c39d49224e0c538d636d74a012/C:/Users/user/Documents/CG/Migration/Inbox/Image/Pasted%20image%2020240702231101.png?1719929461764)

**방법**
- 여러 Point Light를 하나의 Area Light 또는 큰 Point Light로 통합합니다.
- Light Function을 사용하여 복잡한 빛 패턴을 만듭니다.
- Emissive Material을 활용하여 발광 표면을 시뮬레이션합니다.

---

### 1️⃣7️⃣ 라이트 반경 최소화하기

라이트의 영향 범위(Attenuation Radius)가 클수록 더 많은 오브젝트에 영향을 주어 연산량이 증가합니다.

**최적화 팁:**

- 라이트 반경을 실제 필요한 만큼만 설정합니다.
- 불필요하게 넓은 영역을 비추지 않도록 합니다.

---

### 1️⃣8️⃣ Shadow Map 생성 비용

라이트 타입과 이동성(Mobility)에 따라 섀도우 연산 비용이 다릅니다.

**비용 순서 (무거운 것부터)**
1. **Movable/Stationary Point Light**: 6면 큐브맵 섀도우 필요
2. **Movable Directional Light**: 전체 씬에 대한 Cascaded Shadow Map
3. **Movable Spot Light**: 하나의 섀도우 맵만 필요하여 가장 가볍습니다

**최적화 전략**
- 동적 그림자가 필요 없는 라이트는 **Static**으로 설정하여 베이크합니다.
- Stationary Light는 정적 오브젝트는 베이크, 동적 오브젝트는 실시간 그림자를 사용합니다.

> [!tip] 섀도맵 생성 비용
> Point Light > Directional Light > Spot Light 
>
> ❗라이트 반경에 비례

### 1️⃣9️⃣ 빌보드 임포스터 스카이박스

멀리 있는 복잡한 메시를 평면 텍스처로 대체하여 성능을 크게 향상시킬 수 있습니다.

**Impostor란?**

- 3D 메시를 여러 각도에서 렌더링한 이미지를 평면에 매핑합니다.
- 멀리서 볼 때는 실제 3D 메시와 구분하기 어렵지만 렌더링 비용은 매우 낮습니다.

**활용 사례:**

- 배경의 산, 나무, 건물
- 스카이박스의 원경 요소들

### 2️⃣0️⃣ 그림자 드리우기 끄기

그림자를 드리우지 않아도 되는 오브젝트는 **Cast Shadow** 옵션을 끕니다.

**적용 대상:**

- 매우 작은 오브젝트
- 항상 그림자 안에 있는 오브젝트
- 멀리 있어서 그림자가 보이지 않는 오브젝트

## 2️⃣3️⃣ 데칼 최적화

데칼의 비용 처리는 반투명 오브젝트와 유사합니다.

#### 문제점

- 데칼이 겹쳐지면 각각을 모두 렌더링해야 합니다.
- 큰 데칼은 넓은 영역의 픽셀을 다시 계산해야 하므로 무겁습니다.

#### 최적화 방법

- 데칼이 겹쳐지지 않게 배치합니다.
- 데칼 크기를 필요한 만큼만 설정합니다.
- **Decal Blend Mode**를 적절히 선택합니다 (DBuffer Decal이 더 가볍습니다).

## 컬링 시스템

### 2️⃣4️⃣ Drawcall 관리 (드로우 콜)
[[Drawcall]]

**간단한 개념**
- Draw Call은 CPU가 GPU에게 "이 메시를 렌더링해"라고 명령하는 것입니다.
- Draw Call이 많으면 CPU 병목이 발생합니다.

**최적화**
- 메시 병합으로 Draw Call 감소
- Instancing으로 동일한 메시를 효율적으로 렌더링

---

### 2️⃣5️⃣ Occlusion Culling (오클루전 컬링)
[[Occulusion Culling]]
 
**간단한 개념**
- 다른 오브젝트에 가려져 보이지 않는 것은 렌더링하지 않습니다.

**최적화**
- Precomputed Visibility Volume 사용
- 복잡한 실내 공간에 특히 효과적

---

### 2️⃣6️⃣ Frustum Culling (프러스텀 컬링)

카메라의 시야 범위(View Frustum) 밖에 있는 오브젝트는 렌더링하지 않습니다. 
이는 엔진에서 자동으로 처리되지만, 바운딩 박스가 부정확하면 제대로 작동하지 않을 수 있습니다.

---

### 2️⃣7️⃣ HLOD 활용 (Hierarchical Level of Detail)

**간단한 개념**
- 멀리서 볼 때 여러 메시를 하나의 간단한 메시(Proxy Mesh)로 대체합니다.
- LOD와 메시 병합을 자동으로 수행하는 기술입니다.

**설정 방법**
1. **Window → Hierarchical LOD Outliner**를 엽니다.
2.  [[HLOD]] 레벨을 생성하고 거리별 설정을 합니다.
3. Generate Cluster를 실행하여 HLOD 메시를 생성합니다.

## GPU 성능 업그레이드 설정

언리얼 엔진의 GPU 메모리 할당을 조정하여 성능을 향상시킬 수 있습니다.

**설정 경로:**

```
엔진 설치 폴더/Engine/Config/Windows/WindowsEngine.ini
```

**수정 항목:**

```ini
[TextureStreaming]
PoolSizeVRAMPercentage=70
```

이 값은 텍스처 스트리밍에 사용할 VRAM의 비율을 결정합니다. 기본값은 보수적으로 설정되어 있으므로, GPU 메모리가 충분하다면 70~80%로 증가시켜 텍스처 스트리밍 품질을 향상시킬 수 있습니다.

> [!warning] **주의사항**
> - 값을 너무 높게 설정하면 다른 렌더링 작업에 사용할 메모리가 부족해질 수 있습니다.
> - GPU 메모리 용량에 따라 적절한 값을 설정하세요 (예: 4GB GPU는 60%, 8GB 이상은 70~80%).
