이번 포스팅은 시니어 아티스트 린반님의 오픈 강의를 바탕으로, **언리얼 엔진에서 이펙트를 제작할 때 반드시 알아야 할 최적화 기법**을 정리한 글입니다.

이펙트는 게임의 몰입도를 높이는 핵심 요소이지만, 동시에 프레임 저하와 메모리 사용량 증가를 가장 쉽게 유발하는 영역이기도 합니다. 따라서 이펙트 제작 단계부터 최적화를 고려해야 합니다.

본 글에서는 참조 구조 관리, 파티클 시스템 최적화, 머티리얼과 텍스처 관리 등 실무에서 즉시 적용 가능한 핵심 내용을 정리합니다.

## Resource Optimization
### 1. Reference Viewer를 통한 참조 최적화

이펙트 에셋은 보통 다음 구조로 연결 됩니다.

Effect Actor → Animation → Particle → Material → Texture

![[Reference viewer optimization.png]]

정리 순서는 Bottom-Up 순입니다. 예를 들어, 파티클을 삭제하기 전에 애니메이션 노티파이에서 해당 파티클을 제거해야 오류가 발생하지 않습니다.

<br>
- 레퍼런스를 삭제한 후에는 반드시 **'폴더의 리디렉터 고치기(Fix Up Redirectors)'** 를 실행해야 참조 경로가 올바르게 갱신됩니다
	- 리디렉터는 에셋이 이동하거나 삭제될 때 생성되는 임시 참조 파일입니다.
	- 이를 고쳐놓지 않으면 잘못된 경로를 따라 불필요한 로딩이 발생할 수 있습니다.

### 2) Blueprint 최적화

#### 미사용 변수 삭제

미사용 변수를 일괄 삭제하여 블루프린트의 복잡도를 줄일 수 있습니다.

![[미사용 변수 삭제.png]]


변수의 레퍼런스 경로를 확인하려면 변수(또는 노드)를 우클릭하여 '레퍼런스 찾기'를 선택합니다.
찾기 결과 창에서 돋보기 아이콘을 클릭하면 해당 위치로 바로 이동할 수 있습니다.

![[변수 레퍼런스.png]]
<br>

#### Tick 이벤트 사용 제한

- Tick 이벤트는 매 프레임마다 실행되므로 성능에 큰 영향을 미칩니다.
- 가능하면 Timer 함수나 Event Dispatcher를 사용하여 필요한 시점에만 실행되도록 구현하는 것이 좋습니다.
- 불가피하게 사용해야 한다면 **조건문(if)으로 실행 빈도를 제한**하세요.

<br>

#### 프로그래머 검증

최적화 작업 후에는 반드시 프로그래머의 코드 리뷰를 받아 로직의 효율성을 검증받는 것이 중요합니다

### 3) Particle System 최적화

![[모듈 관리.png]]
#### 이미터 정리

- 사용하지 않는 이미터는 즉시 삭제하여 시스템 복잡도를 낮춥니다.
- 이미터 이름을 용도에 맞게 명확하게 지정합니다. (예: Smoke_Main, Spark_Trail)
- 썸네일을 최신 상태로 업데이트하여 에셋 관리를 용이하게 합니다.
- 파티클의 고정 바운드(Fixed Bounds)는 1.2 정도로 설정합니다.
	- 바운드가 카메라 프러스텀(화면 영역)과 조금이라도 겹치면 파티클이 렌더링됩니다.
	- 너무 작게 설정하면 파티클이 화면에서 사라질 수 있고, 너무 크면 불필요한 렌더링이 발생합니다.

#### CPU 부하가 큰 모듈

- **Collision 모듈**: 스폰된 파티클이 다른 오브젝트와 충돌 감지를 할 때 CPU 연산이 발생합니다. 최적화를 위해 파티클 스폰 개수를 제한하거나 Collision 체크를 비활성화하는 것이 좋습니다
<br>
- **Spawn Per Unit 모듈**: 이동 거리에 따라 파티클 스케일을 조정하는 모듈입니다. 값이 클수록 파티클이 작게, 값이 작을수록 크게 생성됩니다
<br>
- **비고정 바운드(Dynamic Bounds)**: 파티클 위치에 따라 바운드를 매 프레임 계산하므로 CPU 부하가 증가합니다. 가능하면 고정 바운드를 사용하세요
<br>

#### 모듈 공유

- 여러 이미터에서 동일한 설정을 사용한다면 모듈을 공유하여 작업 효율성을 높일 수 있습니다.
- 모듈 공유는 **Shift + Drag**로 쉽게 적용할 수 있습니다.

⚠️ Data Type(Vector, Float 등)에 따라 사용 가능한 모듈이 다르므로 체크가 필요합니다.
<br>

#### 루프 이펙트 관리

이미터의 종료 조건을 설정하지 않으면 게임 내에서 계속 실행되어 메모리 누수가 발생할 수 있습니다. **Duration이나 Kill 모듈을 사용하여 명확한 종료 시점을 지정하세요**

![[kill emitter.png]]


#### Light Renderer 최적화

- `Use Inverse Squared Falloff` 옵션 비활성화: 물리적으로 정확하지만 연산 비용이 높습니다
- `반투명에도 적용(Affect Translucency)` 옵션 비활성화: 반투명 오브젝트에 라이팅 계산이 추가로 발생합니다
- 라이트 감쇠는 `Light Exponent` 값으로 조절할 수 있습니다.

### 4) Material 최적화

#### Blend Mode와 Shading Model 설정
##### 기본 이펙트 설정

- **Blend Mode**: Translucent 또는 Masked
- **Shading Model**: Unlit (조명 계산 없음)
- **Render Depth of Field**: 비활성화 (피사계 심도 효과 제외)

##### Base Color가 필요한 이펙트 설정

- **Blend Mode**: Translucent 또는 Masked
- **Shading Model**: Default Lit (조명 계산 포함)
- **Render Depth of Field**: 비활성화
- **Lighting Mode**: Volumetric PerVertex NonDirectional
	- 버텍스 단위 조명 계산으로 성능과 품질의 균형을 맞춥니다

![[라이팅 모드 비고.png]]
#### Material 복잡도 관리

- 머티리얼의 Instructions 수가 적을수록 렌더링 성능이 향상됩니다.
- 뷰포트에서 'Shader Complexity' 모드를 활성화하여 복잡도를 시각적으로 확인할 수 있습니다.
	- 🟢 녹색 : 최적화 쾌적 상태
	- 🔴 빨간색: 최적화 포화 상태

> [!tip] 파라미터 이름은 일관된 규칙으로 작성하여 관리를 용이하게 합니다.
>![[파라미터 이름 규약.png]]

### 5) Texture 최적화

#### POT(Power of Two) 사이즈 사용

- 텍스처 해상도는 2의 거듭제곱(64, 128, 256, 512, 1024 등)으로 제작해야 합니다.
	- GPU는 **POT 규격의 텍스처**를 처리할 때 **메모리 효율성과 밉맵 생성이 최적화**됩니다.
	- 만약 **POT 규격에 맞지 않는 텍스처**는 언리얼 엔진에서 자동으로 리사이징되어 **메모리 낭비가 발생**할 수 있습니다.

#### Alpha 채널 관리

- 알파 채널 사용 여부에 따라 텍스처 용량이 1.5~2배까지 차이가 날 수 있습니다
	- 알파가 필요 없는 경우 `Compress Without Alpha` 옵션을 활성화하세요.
	- 알파채널 여부에 따른 압축자 세팅
		- 알파 채널이 없을 때: **DXT1** 압축 사용 (RGB만 저장)
		- 알파 채널이 있을 때: **DXT5** 압축 사용 (부드러운 알파 보정을 위해 추가 데이터 저장)

#### Texture Group 설정

용도별로 텍스처 그룹을 적절히 지정하면 엔진이 자동으로 최적의 LOD와 스트리밍을 적용합니다.

❗이펙트용 텍스처는 보통 `Effects` 그룹으로 설정합니다.

### 6) Mesh 최적화

#### Collision 설정

- 메시를 임포트할 때 **Auto Generate Collision** 옵션을 비활성화합니다. 
- 필요한 경우 가능한 한 단순한 형태의 콜리전(Box, Sphere)을 수동으로 설정하는 것이 좋습니다
- 복잡한 폴리곤 콜리전은 물리 연산 비용을 크게 증가시킵니다

#### LOD 및 Shadow 설정

![[particle mesh.png]]
- **LOD0 세팅**: 최고 품질 LOD에서도 불필요한 디테일을 제거합니다.
- **Cast Shadow 비활성화**: 대부분의 파티클 이펙트는 그림자가 필요 없으므로 비활성화하여 성능을 향상시킵니다.

## 퍼포먼스 검증 방법

이펙트 최적화 작업 후에는 실제 게임 환경에서 성능을 측정하고 검증하는 과정이 필수적입니다.

#### Shader Complexity 모드

- 뷰포트 상단의 View Mode에서 'Shader Complexity'를 선택하여 화면의 셰이더 복잡도를 시각적으로 확인할 수 있습니다.
- 색상 코드
	- 🟢 초록색: 최적화가 쾌적한 상태
	- 🟡 🟠노란색/주황색: 주의가 필요한 수준
	- 🔴 빨간색: 즉시 최적화가 필요한 상태

#### Frame Rate 확인

콘솔 창(`~` 키)에서 `stat unit` 명령어를 입력하면 실시간 프레임 정보를 확인할 수 있습니다

> [!info] 표시되는 정보
>**Frame**: 전체 프레임 시간
>**Game**: 게임 로직 처리 시간 (CPU)
>**Draw**: 렌더링 처리 시간 (GPU)
>**GPU**: GPU 총 처리 시간

#### Profile GPU

콘솔 창에서 `ProfileGPU` 명령어를 입력하면 GPU 프로파일링 창이 나타납니다

- 현재 화면의 1프레임을 캡처하여 각 렌더링 단계별 소요 시간을 상세히 분석해줍니다
- 이펙트 성능은 **Translucency** 항목에서 측정됩니다.
	- 1.0ms 이하: 양호한 수준
	- 1.0ms 이상: 최적화가 필요한 수준
	- 2.0ms 이상: 즉시 최적화가 필요한 심각한 수준

#### 화면 차지 비율 테스트

`stat unit`을 활성화한 상태에서 카메라를 이동하여 이펙트가 화면을 차지하는 비율을 변화시킵니다
이펙트가 화면을 많이 차지할수록 프레임 속도가 급격히 떨어진다면 **Fillrate 최적화**가 필요합니다

> [!tip] 개선 방법
>- 파티클 개수 감소
>- 머티리얼 인스트럭션 수 감소
>- 텍스처 해상도 조정
>- Overdraw(겹쳐 그리기) 최소화
